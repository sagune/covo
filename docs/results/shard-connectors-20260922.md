# AISHELL 分片连接器实验最终结果（2026-09-22）

两套训练和全部八组验证已完成。MLP 最后一组验证完成于北京时间 2026-09-22 23:42:45。

训练：17,294 条历史 CBSense 分片证据，每套一轮、2,162 个优化步。评估：历史 contextual dev 全部 1,334 条、21,102 参考字、599 个热词标注 mentions。此处不是官方 14,326 条完整 dev。

## 结论

真实音频条件下，两套连接器的 CER 和热词召回均劣于匹配提示词的 9B 纯文本基线。新 Residual 多 79 个字符错误、少 20 个热词命中；MLP 多 75 个字符错误、少 30 个热词命中。

新 Residual 的正确、全零和错配音频结果相近，正确音频分别只改变 23、14 句归一化输出。正确音频相对于这两个音频对照的 CER 差值置信区间均覆盖零，尚无可靠的对应音频收益。

MLP 对音频干预非常敏感：错配音频 CER 达到 82.855%，与正确音频有 1,103 句归一化输出不同。不过正确音频仍差于纯文本和全零对照。这支持“音频分支显著影响输出，但当前纠错结合方式没有带来净收益”；不能把“对音频敏感”等同于“有益的声学纠错”。错配实验本身也不能证明模型是在转写错配语音。

MLP 全零的 CER 为 2.929%，比纯文本少 7 个错误；这一小幅点估计差异不证明声学有效，也没有在此额外计算其相对纯文本的显著性。

## 可比性与留痕

- 所有八组 ID 顺序、输入证据、参考文本相同，每组 1,334 条；两模型 text 预测文件 SHA-256 完全相同。逐条预测散列、指标加总、CER/召回分母已在下载后复核。
- 归一化沿用 restore_eval：NFKC、去空白标点，不做繁简转换。标准答案沿用本次已锁定的历史 contextual dev；与官方 transcript 存在已记录的历史差异，不在本次评分中改动。
- Residual 从零残差初始化；MLP 从历史 Afull 检查点初始化，二者预训练经历不同。不能把全部差异归因于连接器结构。
- 两个 zero 条件实现不同：Residual 在连接器之前把编码器帧置零；MLP 把投影后的音频前缀置零。这是各自分支内的控制条件，不是跨结构完全相同的输入干预。
- mismatch 使用按时长排序的错排，帧数可不同，因此不是严格长度匹配的纯内容干预。
- 既有分片证据和上下文词表来源沿用历史实验；dev 曾被检查过，属于诊断结果，不能作为新的 held-out test。
- 原汇总脚本错误要求 off 文件，而锁定协议仅含 text/true/zero/mismatch。独立 recover_shard_eval.py 保留原始源码、协议、权重、预测和失败日志，完成 residual 指标复核及 MLP 四组推理；没有伪造 off 结果。

# CB-SenseVoice 末端重排序调查与修复（2026-09-14）

调查范围：`src/model/cb_sensevoice.py::_score_shortform_candidates` 及其上游参数。
调优集：AISHELL dev（1334 行 / 599 designated mention）。迁移检查：THCHS-30 test（2495 行）、ST-CMDS held-out（5130 行）。
全部结论均为离线重放或单次声学重跑，**无训练**。归一化统一为 `covo.text.normalize_chinese_text`。

## 1. 重排序现状

`total_score = 1.0·asr_scaled + 1.8·exact_scaled + 0.7·phonetic_scaled + 0.35·consensus − prefix_penalty − insertion_penalty`，
`argmax(total_score)` 与 `asr_top1` 在 1334/1334 行一致 → 该层就是前端 top-1 的产出者。

### 1.1 排序规则对照（AISHELL dev，完整池）

| 规则 | CER | in-pool CER | 召回 | 破坏 |
|---|---:|---:|---:|---:|
| 现状 `total_score` | 3.8053% | 1.4455% | 90.32% | 0 |
| 纯声学 `asr_score` | 7.5064% | 5.3021% | 37.56% | 317 |
| 纯 `search_score` | 4.2792% | 1.9832% | 88.65% | 10 |
| **只按热词** | **3.8101%** | 1.4513% | 90.32% | 1 |
| 只按 consensus | 3.8432% | 1.4918% | 89.98% | 2 |
| 池 oracle | 1.7866% | 0.0000% | 92.15% | 0 |

- **纯声学是灾难** → 热词项是在用加权绕弯实现"必须保住热词"这条约束。
- **六项公式 ≈ 单项热词**（差 1 个编辑）→ 额外复杂度收益≈0。

### 1.2 约束之内不会选

限制在「保住全部受保护热词」的候选子集（均值 10.92 个）内：

| 子集内选法 | CER | 召回 |
|---|---:|---:|
| `total_score` | 3.8053% | 90.32% |
| `asr_score` | 3.8053% | 90.32%（与现状完全相同） |
| 子集 oracle | 1.9050% | 91.99% |

350/1334 行（26%）子集内存在严格更优候选；保留约束的成本仅 0.12pp（vs 全池 oracle 1.7866%）。

### 1.3 十二种 tie-break 规则全部无效

`asr/len`、`asr/√len`、长度惩罚×4、`search_score`、共识支撑数、medoid、字符一致度、覆盖优先……最好的一版只赢 **0.005pp**，多数更差。

### 1.4 缺口解剖：是内容错误，而且声学分反向

- 350 行 / 401 个可回收编辑 = **1.9003pp**。
- **339 行（96.9%）是真实内容错误**（头资→投资、获型→获刑），仅 11 行是数字/标点格式。
- oracle 候选的 `asr_score` **在 100% 的行里都低于**被选中者（均值 −1.68，最大 −0.003）→ 声学分系统性反向。

### 1.5 无偏声学通道（forced-CTC）只有小幅收益

用 `analysis/score_sensevoice_candidate_evidence.py` 对 16 候选池做无偏 forced-CTC 打分：

| 规则 | CER | 召回 |
|---|---:|---:|
| 现状 | 3.8053% | 90.32% (541) |
| forced-CTC + 热词覆盖 tie-break | 3.6821% | 90.32% (541) |
| 子集 oracle | 1.9050% | 91.99% |

双赢但只吃掉缺口的 **6.4%**。

**为什么"有判别力"却"帮倒忙"**：forced-CTC 的 argmax 命中 best-CER 候选的比例 AISHELL 75.7% / THCHS 67.7% / ST-CMDS 63.5%（随机 ~8%），信号真实存在；但它命中时多数行现状本来已最优（增益 0），错过时损失大 → **ST-CMDS 上边际价值为负**。

## 2. 下游接口：强锚点约束是有害的

桥接的 `--trust-asr-top1` 会往提示词里写入「本轮 ASR top-1 来自更可靠的外部/neutral anchor，应视为高置信主候选」，与 selector 系统提示"不要默认保守复制 top-1"直接矛盾。五臂对照（AISHELL dev，全部同 adapter / selector 口径）：

| arm | 变更 | 前端 CER / 召回 | COVO raw | 端到端 restore | 破坏 |
|---|---|---|---:|---:|---:|
| A | 对照：锚点 ON + 原 rerank | 3.8053% / 90.32% | 3.6489% / 73.46% | 2.5922% / 92.65% | 1 |
| **B** | **去强锚点** | 3.8053% / 90.32% | 3.5921% / 73.79% | **2.5495% / 92.65%** | 1 |
| C | 去锚点 + 重排顺序 | 3.6821% / 90.32% | 3.5826% / 73.62% | 2.5543% / 92.65% | 0 |
| D | 去锚点 + 提示词换 forced-CTC 声学分 | 3.8053% / 90.32% | 3.6016% / 73.29% | 2.5543% / 92.65% | 1 |
| E | 去锚点 + 重排 + forced-CTC | 3.6821% / 90.32% | 3.5731% / 73.12% | 2.5543% / 92.65% | 0 |

**去强锚点是唯一有效的单变量改动**（端到端 −0.0427pp）。把提示词里的声学分换成 forced-CTC **没用**。

## 3. 真正的杠杆：候选池上限

### 3.1 瓶颈分解（599 mention）

| 分类 | 条数 | 占比 |
|---|---:|---:|
| 在池内 ∧ KWS 已检索 ∧ 已注入 | 534 | 89.1% |
| 不在池内 ∧ KWS 从未检索到 | 27 | 4.5% |
| 不在池内 ∧ 已检索已注入，但无候选含它 | 20 | 3.3% |
| 在池内但 KWS 没检索到 | 18 | 3.0% |

池外 47 条：**57% 检索漏 / 43% 解码没放进去**；KWS 检索出的 708 词中 84 个（11.9%）从未进入任何候选。

### 3.2 放宽准入参数抬高天花板（AISHELL dev）

变更：`kws_positive_threshold` 0.787→0.5、`kws_topk_per_group` 6→12、`kws_max_prompt_keywords` 28→40、
`prompt_max_injected_keywords` 4→8、`hotword_token_weight` 1.2→2.0、`completion_weight` 0.8→1.2。

**基线复现**：`base`（配置默认）与 9/8 的 `dev.evidence.jsonl` **MD5 完全相同**（`adf5e752aba17e9ffdedce6a0973866f`）。

| run | top-1 CER | top-1 召回 | 池 oracle CER | 池 oracle 召回 | 池外 | 未检索 |
|---|---|---|---|---|---|---|
| original / base | 3.8101% | 90.15% (540) | 1.7913% | 92.15% (552) | 47 | 27 |
| **relax** | **3.5921%** | **93.82% (562)** | **1.5449%** | **94.66% (567)** | **32** | **20** |

**前端自身两轴同时改善**：CER −0.218pp、召回 +22 mention。

### 3.2b 放宽之后的剩余空间（AISHELL dev）

| | CER | 指定热词召回 |
|---|---|---|
| 原配置 top-1 | 3.8101% | 90.15% (540/599) |
| **放宽 top-1** | **3.5921%** | **93.82% (562/599)** |
| 池 oracle（全池 15.95 候选） | 1.5449% | 94.49% (566/599) |
| 池 oracle（保热词子集，均值 10.93） | 1.8150% | 94.32% (565/599) |

- **召回几乎打满**：前端 93.82% 距自己的池 oracle 仅 **0.67pp**（保热词子集内仅 0.5pp）。
- **剩下的 1.78–2.05pp 全是 CER 的选择误差**，且 P2/P2b 已证明声学不可达 → 属于语言侧。
- 保热词约束的代价：CER +0.27pp（1.8150 vs 1.5449），召回 −0.17pp。

### 3.3 归因：放宽的收益来自检索侧还是解码侧

| 数据集 | 检索集均值（base→relax） | 注入均值 | 新准入 mention | 池净增 | top-1 召回增益 |
|---|---|---|---|---|---|
| AISHELL dev | 1.22 → 1.43 | 1.21 → 1.24 | +14（12 个进了候选） | +15（0 回退） | +22 |
| THCHS-30 | 2.15 → 3.10 | 1.85 → 2.31 | +1826（1732 个在 relax 池内） | **仅 +142 净增**（+171 / −29） | **+592** |

**关键发现：THCHS-30 上候选池的内容几乎没变（净 +142），但 top-1 召回涨了 592。**
→ 增益主要来自**更好的选择**（注入词 1.85→2.31、热词 token/completion 奖励 1.2/0.8→2.0/1.2），而不是"捞出更多词"。
这也解释了为什么 THCHS 的池 oracle 只涨 1.0pp，而 top-1 召回涨 4.19pp。

AISHELL 上两侧贡献相当（检索新准入 14、解码新入池 10），池 oracle 因此涨了 2.51pp。

**含义**：六参数放宽里，`prompt_max_injected_keywords` 与两个 `sensevoice_hotword_*_weight` 是"选择侧"杠杆，
`kws_positive_threshold` / `kws_topk_per_group` / `kws_max_prompt_keywords` 是"准入侧"杠杆；两者收益量级因数据集而异。

## 4. 结论

1. **末端重排序在同一候选池上的上限被池 oracle 锁死**：最多 +1 mention / −0.12pp CER。12 种规则 + 3 数据集验证都无法突破，因为所需信号不在现有候选特征里，且声学分方向相反。
2. **重排序的正确形态**是「先保热词约束，再用无偏声学排序」（实现为 `protect + argmax(exact, forced-CTC)`），但单独用它端到端不赚。
3. **召回与 CER 同时改善的真正杠杆是放宽 KWS 准入与注入参数**，它抬高的是池天花板（oracle 召回 92.15%→94.66%），因此连重排序可选的空间也一起变大了。
4. **强锚点约束应当默认关闭。**
5. 端到端 CER 已被 COVO + 字符级还原层饱和在 ~2.55%，前端 CER 的改善传导不过去；但**召回能传导**（92.65%→94.82%）。

## 20. 失败模式的精确定位

### 20.1 不是"覆盖率不够"，是"精确率崩塌"

把出厂各臂与训练臂放在同一张"精确率—覆盖"图上，对比是一边倒的：

| 臂 | 编辑行（占全部） | **编辑精确率** | 净字符 | 可编辑余量实现率 |
|---|---:|---:|---:|---:|
| V-C（出厂） | 344 (6.7%) | **78.5%** | +158 | 9.5% |
| V-D | 367 (7.2%) | **78.2%** | +170 | 10.3% |
| V-A | 334 (6.5%) | 77.5% | +147 | 8.9% |
| LEARN | 297 (5.8%) | 76.4% | +123 | 7.4% |
| **AC-COVO（重训）** | **1926 (37.5%)** | **30.9%** | **−813** | −49.1% |
| 纯文本（重训） | 2133 (41.6%) | 27.1% | −1171 | −70.8% |

**出厂后端的每一次编辑都是赚钱的（78.5% ≫ 66% 盈亏平衡），只是做得太少（13% 覆盖）。
重训把它换成了"做得多、但大多赔钱"（30.9% ≪ 66%）。**

### 20.2 编辑率其实是"对"的，选错了行

AISHELL-train 上 75.4% 的行需要修改，ST-CMDS 上是 35.7%（§10.13）。
重训后的实际编辑率是 **37.5%**，与 ST-CMDS 的 35.7% **几乎吻合**。

所以失效不是"编辑率失准"，而是**在正确的编辑数量下挑错了要改的行**。

### 20.3 根因：目标函数与决策目标不一致

SFT 最大化 `P(reference | input)`，它奖励"只要与输入不同就产出 reference"，即优化**覆盖率**；
而实际决策要求**边际精确率高于盈亏平衡**（增益 1.133 / 损失 0.965 ⇒ P\* ≈ 0.66）。

**这两个目标不是一回事，SFT 训练的是前者。** 重训把 9B 变成了一个更好的"复述器"，
而不是一个更好的"决策者"——两次独立训练（纯文本 27.1%、加声学 30.9%）复现同一模式，
说明这是目标函数的性质，不是声学通道的锅。

声学通道的方向是**对的**（6.6360 优于 7.3109，缓解了过度编辑），但幅度远不足以越过盈亏平衡。

### 20.4 与 §17 的呼应

§17 早已指出瓶颈是"何时该动"而非"能不能选"：正确字在声学 top-5 内占 87.5%，
但任何单字声学门控只能拿回 +48 字（需 +434）。
本节的结论与之一致：**信息在，判据也在，缺的是校准过的决策函数**——
而 SFT 恰恰不训练这个东西。

## 21. 由上述测量推出的新方向

### 21.1 目标其实很近（把算术做准）

净字符与精确率、编辑数的关系是 `net = (2p − 1) · n`。

- 从 **V-C（4.9356%）到 4.5%** 需要净修 `56163 × 0.004356 = 244.6` ⇒ **+245 个字符**；
- V-C 现在 **n = 344、p = 78.5%** ⇒ 理论净 `(2×0.785−1)×344 = 196`（实测 +158，同量级）；
- 若精确率**保持在 78.5%**，达到 +245 需要 `n = 245 / 0.57 ≈ 430` 次编辑。

**也就是：从 344 次编辑增加到约 430 次（+25%），就能到 4.5%——前提是精确率不塌。**

这不是"从零重建"，而是**在一个已经有 78.5% 精确率的余量上多走 25%**。
而且 430 次编辑只占 5130 行的 8.4%，仍然是一个很保守的编辑率。

**唯一真正的未知量：把覆盖从 13.4% 往上推时，边际精确率还能不能守在 66% 盈亏平衡之上。**
这正是新方向要回答的问题。

### 21.3 一个必须先说清的可比性陷阱

**各臂的 `input` 并不相同**，而 `edit_precision.py` 与 `restore_eval.py` 都是相对**各自文件的
input** 计算的。核对后：

| 臂 | input CER | 最终 CER | 编辑数 | 精确率 |
|---|---:|---:|---:|---:|
| V-C / V-A / AC-COVO | **5.2722%** | 4.9356 / 4.9570 / **6.6360** | 344 / 334 / **1926** | 78.5 / 77.5 / **30.9** |
| `e2eSTCMDS` | **5.9060%**（不同 rank-mode） | 5.1279% | **983** | **70.5%** |

同一文件内 input→restore 的自洽性因此不能跨文件比较。**我在初稿里把 `e2eSTCMDS` 的
"+453 字符"与它的 CER 5.1279%（劣于 V-C）并置，误以为矛盾——实际不矛盾，因为它起点更差。**
这条已记录，避免后续再犯。

### 21.4 真正未知的那一段区间

在**同一起点（5.2722%）**上，现有数据只覆盖到 **367 次编辑 / 78.2% 精确率**（V-D），
下一个数据点就是我的 **1926 次 / 30.9%**。**367 → 1900 之间完全空白。**

而不同起点的 `e2eSTCMDS` 表明：**983 次编辑时精确率仍可达 70.5%** —— 这是"高覆盖下
精确率未必崩塌"的存在性证据，但因为起点不同，只是提示而非证明。

同时，§12 早已测出：池内提议在**全部 1461 个可编辑行**上的平均精确率只有 **43.5%**
（min-edit 规则），**低于盈亏平衡**。所以曲线是**陡降**的：344 次时 78.5%，1461 次时 43.5%。

由 `net = (2p−1)·n` 反解目标：要净 +245 字符，
- 若 p = 0.70 ⇒ 需要 **n ≈ 612** 次编辑；
- 若 p = 0.66 ⇒ 需要 **n ≈ 766** 次编辑。

**所以问题被压缩成一个单一、可测的问题：在同一起点上，把编辑数从 344 推到约 600–770 时，
精确率能否守在 66% 以上？** 这是下一步唯一需要先回答的事，且它决定了整条路是否成立。

### 21.2 方向：冻结出厂后端，只学"接受/拒绝"的选择器

**不做 9B 微调。** 保持出厂后端的权重不变，输出它的改写提议，再训练一个**选择性门控**
决定是否接受该提议；门控用决策论效用（增益 1.133 / 损失 0.965）训练，
阈值在 AISHELL-dev 上校准，ST-CMDS 一次性迁移。

为什么这条路避开了本次失败：

1. **不可能比基线更差**——门控说"不接受"时，输出等于基线；
2. **出厂后端的提议本身是赚钱的**（78.5% ≫ 66%），任务是**扩大覆盖而不是改变行为**；
3. **参数量小**（一个判别式门控，不是 9B 微调），不会被 AISHELL 的 75.4% 编辑先验带偏；
4. **直接对准测出的瓶颈**（固定精确率下的覆盖），而不是试图让模型"更会改"。

**声学证据的位置也随之改变**：不再注入到生成器的输入 embedding（本次证明这样会引入
净负面偏置），而是作为**门控的特征**——这正是 §17 测量出信息所在的位置。

### 21.5 可立即验证的前提

**决定性测量（不需要训练）**：把"367→1000 次编辑"这段区间补出来。做法是拿**冻结的出厂后端**
在**同一输入（5.2722%）**上，按某个现成排序量对 1461 个可编辑行排序，逐点报精确率与净字符，
看曲线在哪个 k 穿过 66%。

- 若在 k ≈ 600–770 处仍 ≥66% ⇒ 该方向成立，值得投入门控训练；
- 若在 k ≈ 450 就跌破 66% ⇒ **这条路同样不通**，应如实记为负结果并停止。

这条测量只需要**已有的池文件与前端分数**，不需要 GPU 训练，也不需要新的声学前向。
`selector_operating_curve.py` 与 `gate_operating.py` 已经在仓库里，可直接复用。

**而且要明确一点**：即使曲线成立，成功的判据仍是 §AC.5 那六条预注册门槛 + 证伪条款，
且**必须保持"不改动出厂后端权重"**——本次失败已经证明，任何形式的 SFT 微调都会把
78.5% 的精确率砸到 30%，因为 SFT 优化的是覆盖率而不是决策。

## 22. 重新想办法：把声学证据从"生成"移到"否决"

### 22.1 先纠正一个极易误读的数字

`selector_operating_curve.py` 的参考点里有一行：

```
零训练 min-edit 规则（只在需要的行上用）  a=43.5%  k=100%  ->  CER 3.9903%  ✅ 达标
```

**这个 3.9903% 是 oracle 弃权，推理时不可得，不能当作成果。** 同表的反面是：
「min-edit 规则，**所有行**」→ **10.7847%**，编辑 **5122/5130** 行。

"只在需要的行上用"是用**参考文本**挑行的。§12 因此早就写明：
**选择已经可解**（零训练规则 43.5%，在 `k≈0.95` 时只需 `a≥36.9%`）；
**瓶颈是弃权 `k`**。

**AC-COVO 这一跑精确复现了这个结构**：训练生成器 a=20.9%、k=0% → 10.95%；
我这次重训臂的 k 同样接近 0（编辑 1926/5130 行），于是 5.2722% → 6.6360%。
**本次失败没有推翻 §12，而是又一次确认了它。**

### 22.2 新想法：声学 top-5 的正确用法是"否决"，不是"生成"

§17 测出的是**条件命中率**：在**已经确定某位置出错**的前提下，正确字有 87.5% 落在
声学 top-5 内。这个测量**不蕴含**"能用它生成更好的候选"——本次实验证明用它做生成条件
反而是净负面（消融 −0.44 pp）。

但它**直接蕴含一个否决规则**：

> 若某次提议要把位置 p 的字改成 X，而 **X 不在该帧的声学 top-5 内**，
> 则该提议缺少声学依据，应当**否决**。

这把 §17 的测量用在**它真正成立的方向上**：不是"挑出正确的字"，而是"筛掉声学上不可能的
字"。而且它与 §12 的瓶颈（弃权 `k`）**正面对齐**——否决规则的作用恰恰是抬高 `k`。

### 22.3 为什么这次可能奏效，而之前的门控没有

之前的门控用的都是**单字置信度**（logp、margin、熵）。§17 已表明这类量在 4.70% 的
基础错误率下无法分离（最优工作点只敢动 61 个位置）。

**否决规则用的不是置信度，而是"提议的目标字是否属于候选集"** ——
这是集合成员关系而非阈值比较，对同音字错误尤其有效：同音字在声学分布里置信度很高
（所以置信度门控必然失效），**但错误的同音字替换目标往往不在 top-5 内，而正确字在**。

### 22.4 可以立刻验证，不需要 GPU

用**已有**数据即可端到端模拟：

1. 取 ST-CMDS 的 1461 个决策行；
2. 对每行套用零训练 min-edit 规则得到提议；
3. 对提议中每个被改动的字符位置，检查目标字是否在该帧声学 top-5 内
   （数据已在 `stcmds_allowed_sets.jsonl`，与提议字符共用同一 raw 索引）；
4. 对被否决的提议整行弃权（保持 top-1）；
5. 报 `(a, k)` 与最终 CER，并扫描否决强度画出精确率—覆盖曲线。

**预注册判据**：若存在某个否决强度使 CER < 4.9356%（基线），则方向成立、值得做门控；
若最优仍在 ~4.9% 以上，则与本次一样如实记为负结果并停止。

**这条路径不需要训练、也不需要改动任何出厂权重**，因此不会重蹈本次
"用 SFT 把 78.5% 精确率砸成 30.9%" 的覆辙。

## 1. Method

### 1.1 问题设定

CB-SenseVoice 是词表驱动的上下文 ASR：给定音频与任务词表，先由 KWS 检索热词、经短语
cross-attention adapter 与 context-biased CTC prefix beam 解码，对每条 utterance 输出
一个 top-1 假设 `old` 与一个带分数的候选池 `pool`（本文实验里 |pool| ≈ 8–16）。
**末端重排序**（rescorer）的职责是在 `pool` 内重新选一条作为最终 `asr_top1`。

该层是 top-1 的**产出者**而不是后处理器：`argmax(total_score)` 与 `asr_top1` 在
AISHELL dev 上 **1334/1334 行一致**，其中
`total_score = 1.0·asr_scaled + 1.8·exact_scaled + 0.7·phonetic_scaled + 0.35·consensus − prefix_penalty − insertion_penalty`。

### 1.2 两个缺陷（本文的发现）

**缺陷 1（主键是护栏，不是选择器）。** `exact_weighted_score` 是热词精确覆盖统计，取值基本只有
{0, 0.5, 1}。实测它并不"惰性"：

| 池 | 行数 | 全 0 池 | 池内取值 ≥2 种 | **top-1 已是池内最大** |
|---|---:|---:|---:|---:|
| AISHELL dev | 1334 | 7.4% | 75.5% | **99.3%** |
| THCHS-30 | 2495 | 20.3% | 67.5% | **98.4%** |
| ST-CMDS | 5126 | 71.8% | 21.7% | **98.0%** |

→ 主键的作用是"保住前端的热词覆盖判断"（top-1 在 98–99.5% 的行上已取最大值），
**真正的选择发生在覆盖相同的候选之间，那里只有声学项说话**。

**缺陷 2（声学项有长度偏置）。** `score_sensevoice_candidate_evidence.py::ctc_sequence_score`
返回 `F.ctc_loss(..., reduction="none")` 的**总和**（未按目标长度归一化）并直接存入 `asr_score`。
于是出厂规则实际退化为 `argmax(asr_score)` —— 一个随发射 token 数单调下降的分数。
在全部 (句, 候选) 对上直接测量：

| 池 | 对数 | r(len, 总LL) | dLL/token | r(len, LL/n) | 池内长度极差 |
|---|---:|---:|---:|---:|---:|
| AISHELL dev | 21218 | −0.044 | −0.072 | +0.289 | 0.53 |
| THCHS-30 | 39920 | +0.009 | +0.007 | +0.233 | 0.59 |
| **ST-CMDS** | 71343 | **−0.442** | **−1.193** | +0.438 | **0.81** |

**域依赖的原因**：出厂重排把假设**改短**的行占比是 AISHELL **0.07%**（1/1334）、
THCHS-30 **0.24%**（6/2495）、ST-CMDS **4.4%**（227/5130）——**相差 60 倍**。
域内几乎没有可删的余量，缺陷不可见；ST-CMDS 有，于是暴露。

### 1.3 修复规则

对每条 utterance，令 `old` 为前端 top-1、`P` 为出现在 `old` 中的提示词热词集合：

```
pool  = 池内已被 forced-CTC 打分的候选
sub   = { c ∈ pool : 每个 p ∈ P 都出现在 c 中 }        # 保护：不丢已有热词
sub   = { c ∈ sub  : |c| >= |old| }                      # 只增不减
new   = argmax_{ c ∈ sub } ( exact_weighted_score(c) , ctc_loglik(c) / n_tokens(c) )
```

**无自由度**：长度归一化就是除以 token 数；只增不减的门槛就是 `|old|` 本身；
主键保持出厂设置。因此**没有任何数值是在迁移集上调出来的**。
唯一的二选一是"保留还是丢掉 `exact_weighted_score` 主键"，依据是先验的——重排不应推翻
前端已经做出的热词覆盖决定。

### 1.4 形式化保证

因为 `old` 自身含 `P` 的全部短语、且 `|old| >= |old|`，所以 **`old ∈ sub`** 恒成立，
即 `old` 始终是 argmax 的一个可行点。于是：

| | 陈述 | 成立原因 |
|---|---|---|
| **G1** | `|new| >= |old|`（绝不缩短） | 可行域限制 |
| **G2** | `ews(new) >= ews(old)`（覆盖不降） | `old` 可行 |
| **G3** | `P` 中每个短语仍出现在 `new` 中（保护不破） | `old` 可行 |

第五条实测：五组池逐行计数，修复版 G1/G2/G3 违规 **0 / 0 / 0**；出厂重排只违反 G1，
违规数 1 / 1 / 6 / 4 / **227**（对应上表的 0.07% / 0.24% / 4.4%）。
即**出厂重排从来不是"覆盖"问题，它唯一的缺陷就是允许删除**。

> **不得过度声称**：G1–G3 **都不蕴含**指定热词召回不降。`ews` 度量的是**被注入提示词的热词**
> 覆盖度，不是 held-out 的 designated 列表。请勿把 G2 写成"召回保证"。

### 1.5 成本

- 计算：纯 CPU，只做字符串包含与长度比较 + 已有的分数查表；5130 条 utterance 秒级。
- 约束的 oracle 代价（"有 floor 的池 oracle" − "无 floor 的池 oracle"）：

| 池 | 池 oracle | 限只增不减 | 代价 | 需要更短候选的行 |
|---|---:|---:|---:|---:|
| AISHELL dev 原 / 放宽 | 1.7913% / 1.5449% | 1.8055% / 1.5733% | 0.014 / 0.028pp | 3 / 4 |
| THCHS-30 原 / 放宽 | 2.1654% / 2.1432% | 2.2049% / 2.2196% | 0.039 / 0.076pp | 29 / 38 |
| ST-CMDS 原 / 放宽 | 1.9372% / 1.9176% | 2.0084% / 1.9978% | 0.071 / 0.080pp | 38 / 41 |

→ 只让掉 **0.014–0.080pp** 的 oracle 头寸（<1.6% 的行才需要更短候选）。

## 2. Experiments

### 2.1 设置

- **调优集**：AISHELL dev（1334 行 / 599 designated mention）。
- **一次性迁移检查**：THCHS-30 test（2495 行 / 14137 mention）、ST-CMDS held-out（5130 行 / 1718 mention）。
- **两种准入设置**：`原准入` 与 `放宽准入`（六参数的广度组 + 插入强度组，见 §4）。
- **前端指标**：top-1 CER、指定热词召回、**池 oracle CER/召回**、**选择误差**（top-1 CER − 池 oracle CER）、
  伪插热词数、长度漂移。
- **下游指标**：COVO 端到端 CER / 召回（`restore[deployable]`，字符级保护还原层）、**保护跨度破坏数**。
- 归一化统一 `covo.text.normalize_chinese_text`；无训练。

### 2.2 主结果（前端）

修复后（放宽准入 + 修复重排）相对原准入基线：

| 数据集 | 基线 top-1 CER / 召回 | 修复后 CER / 召回 | ΔCER | Δ召回 |
|---|---:|---:|---:|---:|
| AISHELL dev | 3.8101% / 90.15% | **3.5257% / 93.66%** | **−0.2844pp** | **+3.51pp** |
| THCHS-30 | 3.4681% / 86.52% | **3.1982% / 91.21%** | **−0.2699pp** | **+4.69pp** |
| ST-CMDS held-out | 5.7921% / 92.43% | 5.90xx% / 93.31% `[待填]` | +0.11pp（由准入造成） | +0.88pp |

**两个杠杆的分工必须分开写**：放宽准入买**召回**（+3.5 ~ +4.7pp），修复后的重排买 **CER**
（同一准入内 −0.005 ~ −0.119pp，且从不退化）。重排单独对召回的贡献 <1pp。

### 2.3 消融（ST-CMDS held-out，原准入，ΔCER 相对基线）

| 配置 | top-1 CER | ΔCER |
|---|---:|---:|
| 出厂重排 | 6.5417% | **+0.7496pp** |
| + 长度归一化 | 6.1250% | +0.3330pp |
| + 只增不减 | **5.7867%** | **−0.0053pp** |
| 只增不减但丢掉 `ews` 主键 | 5.7529% | −0.0392pp（但 THCHS-30 召回 −1.32pp） |

两处改动的作用正好可加：**0.417 + 0.338 = 0.755pp**，即出厂重排的全部伤害。

### 2.4 域内代价与跨域收益（配对 bootstrap，2000 次按句重采样）

| 池 | 对比 | ΔCER pp [95% CI] | Δ召回 pp [95% CI] | P(两轴不劣) |
|---|---|---:|---:|---:|
| AISHELL 原 | 前端 top-1 | −0.1185 [−0.2384, +0.0000] | +0.17 [+0.00, +0.52] | 0.980 |
| AISHELL 放宽 | 前端 top-1 | −0.0663 [−0.1900, +0.0576] | −0.17 [−0.52, +0.00] | 0.324 |
| THCHS-30 原 | 前端 top-1 | **−0.1122 [−0.1518, −0.0715]** | +0.07 [−0.39, +0.52] | 0.658 |
| THCHS-30 放宽 | 前端 top-1 | **−0.0789 [−0.1270, −0.0284]** | **+0.50 [+0.13, +0.89]** | **0.995** |
| ST-CMDS 原 | 前端 top-1 | −0.0053 [−0.0692, +0.0621] | +0.17 [−0.06, +0.43] | 0.546 |
| **ST-CMDS 原** | **出厂重排** | **−0.7549 [−0.8313, −0.6728]** | +0.00 | **1.000** |
| AISHELL 原 / 放宽 | 出厂重排 | +0.0095 [+0.0000, +0.0239] | +0.00 | 0.145 |
| THCHS-30 原 / 放宽 | 出厂重排 | +0.0123 [+0.0037, +0.0234] | −0.04 ~ −0.06 | 0.002–0.003 |

**一句话**：用 **0.010–0.012pp 的域内 CER** 换 **0.755pp 的跨域鲁棒性**，任何一格都不劣化。
诚实标注：AISHELL 放宽与 ST-CMDS 原的 CER 改善 **CI 含 0**（是"不劣化"而非"显著改善"）；
只有 THCHS-30 放宽两轴同时显著。

### 2.5 选择误差（前端 top-1 CER − 池 oracle CER）

| 池 | 池 oracle CER | 基线选择误差 | 修复后选择误差 |
|---|---:|---:|---:|
| AISHELL dev 原 / 放宽 | 1.7913% / 1.5449% | 2.0188 / 2.0472pp | **1.9003 / 1.9808pp** |
| THCHS-30 原 / 放宽 | 2.1654% / 2.1432% | 1.3027 / 1.1339pp | **1.1906 / 1.0550pp** |
| ST-CMDS 原 | 1.9372% | 3.8549pp | **3.8495pp** |

ST-CMDS 的选择误差（3.85pp）是另两域（1.1–2.0pp）的两倍以上，与它 7.52% 的伪插基数一致。

### 2.6 下游（COVO）`[部分未验证]`

**已测（均为出厂重排口径）**：

| 数据集 | 基线 e2e CER / 召回 / 破坏 | 原准入+出厂重排 | 放宽+出厂重排 |
|---|---|---|---|
| AISHELL dev | 2.5922% / 92.65% / 1 | — | 2.5495%（F1 不重排）/ 2.5732%（F2 重排）/ 94.82% / 1 |
| THCHS-30 | 3.2241% / 91.27% / 162 | — | 3.1674% / 93.96% / **110** |
| ST-CMDS held-out | 5.0300% / 93.48% / 0 | **6.2657% / 92.90% / 0** | 5.1279% / 94.00% / 0 |

**关键负例**：冻结准入、只把出厂重排打开，ST-CMDS 端到端从 5.0300% 掉到 **6.2657%（+1.2357pp）**，
比放宽准入的 +0.0979pp 大 12.6 倍；且强制标注集口径（6.2052%）也修不回来
—— **COVO 的字符级保护层只保证"不破坏跨度"，不负责"修错"**。

**`[未验证]` 修复重排的端到端正例**：AISHELL / THCHS-30 / ST-CMDS（放宽，以及 ST-CMDS 原准入）
的 COVO 推理尚未运行。因此当前**不能**声称"修复不损害下游"，只能声称
"修复消除了已知的下游损害来源"。

### 2.6.1 后端（COVO）到底瓶颈在哪：选择 vs 编辑，以及"接口外基线"

这一节回答一个此前只有全局数字的问题：**冻结前端后，COVO 的编辑花在了哪里，剩下的空间是什么性质。**
所有数字都是 `restore[deployable]` 口径，并用 `covo_error_anatomy.py --policy deployable` 逐位复现官方数字
（ST-CMDS 4.9356% / THCHS-30 3.1674% / AISHELL dev 2.5874%），因此行为视角与指标视角不会各自漂移。

**（1）ST-CMDS 的病是"欠编辑"，不是"改错"**（把每行按后端相对输入做了什么分类）：

| 行为 | 行数 | 占比 | e_in | e_out | 净编辑 |
|---|---:|---:|---:|---:|---:|
| `no_change`（原样复制 top-1） | 4786 | **93.3%** | 2335 | 2335 | 0 |
| `sel_win` / `sel_loss` | 167 / 45 | 3.3% / 0.9% | 277 / 47 | 98 / 97 | **−179** / +50 |
| `edit_win` / `edit_loss` | 56 / 16 | 1.1% / 0.3% | 146 / 26 | 62 / 50 | **−84** / +24 |

净损失（`sel_loss`+`edit_loss`）= **74 字符**，而 `no_change` 那 4786 行里有 **1198 行"更好的候选就印在
提示词的编号列表里却被原样跳过"**，价值 **1341 字符 = 2.39pp** —— 是净损失的 **18 倍**。
同一族 adapter 在 THCHS-30 上改 36.8% 的行、AISHELL dev 上改 28.0%，ST-CMDS 上只改 6.7%：
**5 倍的编辑倾向差是校准差异，不是能力差异。**

**（2）当前收益的一半以上来自"编辑"而不是"选择"**（按 reference 是否可达候选池切开）：

| ST-CMDS V-C | 行数 | 字符 | 输入 CER | 输出 CER | 收益 |
|---|---:|---:|---:|---:|---:|
| ref **在**池内（选择可及） | 4419 | 48031 | 2.7024% | 2.5317% | **+82（43%）** |
| ref **不在**池内（只能生成） | 711 | 8132 | 20.4501% | 19.1343% | **+107（57%）** |
| 合计 | 5130 | 56163 | 5.2722% | **4.9356%** | **+189** |

选择的可回收空间是 **1169 字符**（输入误差 − 可见候选最优误差），当前只实现 **+82 = 7.0%**。
THCHS-30 上"选择"这一侧甚至是**负的（−130 字符）**，整体 +15 全靠编辑 +145 兜底
—— 这是"该模型根本没在做选择"的直接证据。

**（3）生成层面的独立指纹**（在任何后处理之前，用原始生成文本对比证据池）：

| 原始生成 | ST-CMDS | THCHS-30 | AISHELL dev |
|---|---:|---:|---:|
| == 前端 top-1（抄输入） | **93.1%** | 57.4% | 60.9% |
| == 可见 n-best 候选（**选择**） | **4.8%** | 13.7% | 14.9% |
| 不在池内（**生成/编辑**） | **1.8%** | 27.0% | 19.0% |
| 恰好等于 reference | 66.2% | 50.9% | 68.6% |

与 (1) 在**生成层**互相印证：ST-CMDS 上输出有 93.1% 的行**根本没落到候选列表上**，
所以后续的字符级保护层不可能救回这些行。THCHS-30 敢写（27.0% 池外）却写不对，说明
"敢编辑"与"编辑正确"是两种不同能力。

**（4）出厂基线是"接口外"测得的（这一条影响所有下游数字的解读）**

读出两个出厂 adapter 的**原始训练文件第一行**后确认，界面差异是**四处同时改变、其中两处把目标反过来**：

| | 训练时（`train.cb-hardnegative.qwen.jsonl`, 138,180 行） | 本工作推理时 |
|---|---|---|
| system | `…保守的中文ASR后纠错器…`**`证据不足时保持第一候选`**（100 字符） | `…候选选择器…`**`不要默认保守复制 top-1`**（165 字符） |
| user | `N-best文本：`/`N-best拼音：` 纯列表（682 字符） | `ASR top-1:` + 保护热词 + 可靠性标签 + 稳定片段 + 热词证据（1260–2651 字符） |
| 结尾 | `请输出：{"text":"…"}` | `请输出 JSON：{"text":"…"}` |
| `max_length` | **1024**（p99 提示词 1631 ⇒ 当年 31% 的行被截断） | 2048 |

**后果**：出厂 COVO 的端到端数字衡量的是"一个保守纠错器被要求当选择器用"，
**不是 COVO 的选择能力上限**；(1) 中 93.3% 的 `no_change` 正是它忠实执行"证据不足就保持第一候选"的结果。
任何引用出厂下游数字的对比都应标注这一点。

**（5）为可复现性做的两项核验**（都是脚本化的，不是断言）

- **泄漏红线**：训练 17,301 行 `dataset` 全为 `aishell`、`split` 全为 `train_covo_shard*`；
  与 ST-CMDS / THCHS-30 held-out 的**完全 reference 重叠 0 / 0**、**uttid 重叠 0 / 0**；
  扫描 581,719 条训练文本（reference + 全部可见候选 + 全部热词）后，**共享 8-gram 为 0**（仅 6 字通用短语重合）。
  注意 `train_sft.jsonl` 的 `id` 只有 1000 个不同取值（分片内位置索引，**不是** AISHELL uttid），
  所以泄漏核验**只能**基于文本。
- **界面一致性**：在**全部 17,301 行**训练提示词与三个推理臂上验证——system / 结尾 / 候选列表表头**逐字节相同**，
  标签顺序唯一，且**推理出现的提示词骨架"训练从未见过"的个数为 0**（含 ST-CMDS 373 行候选不足 8 条的形状）。
  另外 JSON 解析失败率在四个出厂臂共 10,293 行上是 **0.000%**，因此它是硬基线而非阈值。

### 2.6.2 编辑的精确率 / 覆盖率权衡，与过编辑压力

§2.6.1(1) 说 ST-CMDS"欠编辑"，这容易被读成"让它多改就行"。把"改得对不对"与"改得多不多"分开之后，
结论要精确得多，而且**修正了那句话**：

| | ST-CMDS V-C | THCHS-30 | AISHELL dev |
|---|---:|---:|---:|
| 编辑行数（占全部行） | 344（**6.7%**） | 917（**36.8%**） | 374（**28.0%**） |
| 有益 / 有害 / 无变化 | 223 / 61 / 60 | 378 / 354 / 185 | 239 / 79 / 56 |
| **编辑精确率** | **78.5%** | **51.6%** | **75.2%** |
| 字符 得 / 失 | +232 / −74 | +397 / −532 | +280 / −97 |
| 净字符 | **+158** | **−135** | **+183** |
| 可编辑行（提示词里可见更好候选） | 1461（28.5%） | 617（24.7%） | 317（23.8%） |
| **覆盖率** | **13.4%** | **44.4%** | **64.4%** |
| 可编辑空间的净实现率 | **+9.5%** | **−18.2%** | **+51.3%** |

**关键：精确率并不会因为"改得多"而必然崩塌。** AISHELL dev 在 28.0% 的编辑率、64.4% 的覆盖率下，
精确率仍有 **75.2%**，净实现率 **+51.3%**，是三域里最好的；只有迁移域 THCHS-30 在 36.8% 的编辑率上
掉到 **51.6%** 并净亏 **−135 字符**。按字符加权（受助编辑平均赚 `得/有益`，有害编辑平均赔 `失/有害`），
**盈亏平衡精确率约为 51–59%**（ST-CMDS 53.8% / AISHELL dev 51.2% / THCHS-30 58.9%）。
⇒ 安全操作区间大致是**编辑率 ≲ 30%**：AISHELL dev 在 28% 上证明确实可行，THCHS-30 在 37% 上崩掉。
换言之，ST-CMDS 现在"精确（78.5%）但不敢改（覆盖率 13.4%）"，**提高覆盖率是主要机会**；
风险只在于冲过约 37%。

**过编辑压力可以定量**。训练目标就是 reference，所以"目标与输入不同的行占比"就是模型学到的
"该改多少"的先验：

| 集合 | 行数 | reference ≠ top-1 | 可见 n-best 里存在更好候选 |
|---|---:|---:|---:|
| **训练集（AISHELL train）** | 17,301 | **75.4%** | 61.4% |
| ST-CMDS held-out | 5130 | **35.7%** | 28.5% |
| THCHS-30 | 2495 | 46.3% | 24.7% |
| AISHELL dev | 1334 | 32.8% | 23.8% |

即**训练把"该改"的先验定在 2.1 倍于 ST-CMDS 的真实比率**。而实测编辑率（ST-CMDS 6.9% /
AISHELL 39.1% / THCHS 42.6%）**全部低于这个先验**，因为出厂 adapter 的"保守纠错器"界面在压着它（§2.6.1(4)）。
一旦界面校准，编辑率向先验靠近几乎是必然的，**而 ST-CMDS 只需要 35.7%**——
所以本工作把守住**精确率 ≥ 70%**（而非编辑数量）作为该阶段的硬性回退判据。

**口径提示**：上表第三列（可见 n-best）与 §9.8 那个 73.4% 不同，后者用**完整池**
（可见 + `cbwhisper.candidates`）；两者在训练集上差得多（61.4% vs 73.4%），
因为"可见 vs 全池"的 3.33pp 差距是训练集独有的现象，在评测集上两者接近。引用时须写明口径。

### 2.7 下游接口一致性

提示词把重排后的 winner 放在 n-best 第 1 行，但那一行自带的 `rank=/score=` 是**原始**排名与分数，
于是可能出现"第 1 行元数据把它排在第 2 行之下"的内部矛盾。发生率（可见分数倒挂）：

| run | 可比行数 | 倒挂率 | line1 平均原始 rank |
|---|---:|---:|---:|
| ST-CMDS 原 + 出厂重排 | 5126 | **12.5%** | **1.75** |
| ST-CMDS 原 + 修复重排 | 5126 | **5.7%** | **1.15** |
| AISHELL 放宽 + 出厂 / 修复 | 1334 | 10.8% / **10.8%**（相同） | 1.25 |
| THCHS-30 放宽 + 出厂 / 修复 | 2495 | 11.7% / **11.6%** | 1.26 / 1.25 |

修复在迁移域把倒挂降到 **2.2 倍好**，域内无变化（只增不减极少触发）。
残留倒挂是桥接层的渲染选择，建议 `format_nbest` 一并透出重排后的名次与分数。

### 2.8 被否定的方案（建议写进附录，避免重复劳动）

12 种 candidate tie-break 规则（最好只赢 0.005pp）、纯声学排序（CER 7.5064% / 召回 37.56% / 破坏 317）、
采样解码救热词（多数票只救回 3.6%，control 组 100% 的行被弄坏）、think 模式（25% JSON 解析失败）、
`--trust-asr-top1` 强锚点、把提示词声学分换成 forced-CTC、与前端自身分数的 z-score 混合、
信任域、hotword-set 冻结、bounded edit、hotword-noloss / gain-only 门、丢掉 `ews` 主键、
严格加长（δ=+1，ST-CMDS +2.998pp）。

## 3. Limitations

1. **下游正例缺失（部分已补）**：ST-CMDS 原准入 + 修复重排的端到端**已完成且仍高于基线**（5.5214%，§4.1）；
   AISHELL / THCHS-30 的修复重排端到端正例已完成（§2.4）。**仍未闭环的是后端训练能否把
   ST-CMDS 从 4.9356% 推到 4.5%**（§4.2），这是投稿前必须有的结论；若推不到，本文的结论
   就应当写成"前端已到顶、且文本后纠错吃不下剩余选择误差"，这本身是可发表且有用的负结果。
2. **G2 ≠ 召回保证**：`ews` 是注入提示词的热词覆盖，不是 held-out 指定列表（§1.4）。
3. **ST-CMDS 仍有 +0.11pp**：完全来自放宽准入，与选择层无关；原因是该域伪插基数高（7.52%）。
   处置选项：(a) 按域声明为 opt-in；(b) 只放宽"广度组"（`[未验证]`，脚本已带自门控）；
   (c) 把 ST-CMDS 从主结果移到附录。
4. **代码漂移**：THCHS-30 的 08-11 证据与当前代码不同（3.4681% → 3.4361%，召回 +0.53pp），
   所有对比都已修正到同代码基线；AISHELL 无漂移（MD5 逐字节一致）。
5. **两套前端口径差 1 个编辑**（AISHELL 3.8101% vs 3.8053%），已在内部文档标注，引用时不要混用。
6. **"召回与 CER 同时改善"是对整套前端改动成立**，不是对重排单独成立（§2.2）。

| 项 | 内容 |
|---|---|
| 目标 | ST-CMDS 端到端 CER 从 **4.9356%** 到 **4.5%**，召回不降（现 95.98%）、保护跨度破坏不增（现 0） |

# AC-COVO：声学条件化的第二遍纠错（论文方法节草稿）

本节给出 AC-COVO（Acoustic-Conditioned COVO）的方法描述。与 §2.6 的
"选择器/编辑器"路线不同，本节的组件是**在两个模块之间新增一个可训练的耦合件**，
其设计不是先验选择，而是由 §17 的测量逐条逼出来的。

---

## AC.1 缺口定位：内容在、判据在、门控不在

CB-SenseVoice 的前端 top-1 在 ST-CMDS 上是 5.2516% CER。把它的强制对齐结果
（发射帧）与参考文本逐字比对，并对**每一个字符**记录该帧 CTC 分布的前 5 个候选
（排除 argmax 自身），得到三个量：

| 量 | 值 | 含义 |
|---|---:|---|
| 参考字落在声学自分布 top-5 内 | **87.50%** | 内容在 |
| 参考字就是第一备选 | **58.82%** | 判据在（> 54% 盈亏平衡） |
| 纯声学门控的最优净收益 | **+48 字**（需 +434） | 门控不在 |
| 逐帧 top-5 oracle CER | **1.1611%** | 可修空间 4.09 pp |

按 top-1 自身对数概率三分位分层，命中率分别为 84.00% / 91.66% / **86.86%**——
**即使模型最自信的三分之一，正确答案仍在它的备选里**。这解释了同音字错误
（如 凶/胸）的机制：**信息在，只是排序错了**，因此任何单调依赖"置信度"的门控
都无法触及它们。

对照：完整 24 候选句级 N-best 池的 oracle 是 2.3254%，而逐帧 top-5 的 oracle 是
**1.1611%**，好一倍。原因是 N-best 只包含前端"愿意成句输出"的替代，而逐帧分布
包含前端**从未提出**的单字替换。**⇒ 注入通道必须是逐帧候选分布，而非 N-best 列表。**

结论：CTC 头有**声学**没有**语境**，语言模型有**语境**没有**声学**；
缺失的是一个同时读到两者的**联合函数**。AC-COVO 就是该函数。

## AC.2 组件：逐字符声学条件化

```
音频 ─► CB-SenseVoice 编码器（冻结）─► 逐帧隐状态 H ∈ R^{T×512}
                                        │
                                        │  取每个假设字符的发射帧 f_i
                                        ▼
                        投影层（可训练）P: R^512 → R^{d}
                                        │
                                        ▼
      h_i ← Embed(c_i) + P(H[f_i])      （加性注入，序列长度不变）
                                        │
   文本提示（候选表 + N-best）───────────┤
                                        ▼
                     Qwen3.5-9B（LoRA 可训练）
                                        ▼
                 受限解码：逐位置仅允许声学可信字符集
```

**四个由测量决定的设计选择：**

1. **输入是逐帧隐状态，不是句级摘要。** AC.1 的 87.5% 是**逐帧**统计量；
   句级池化会抹掉它赖以存在的位置信息。
2. **加性注入而非前缀拼接。** 序列长度与纯文本接口完全一致，每个位置
   严格对应它自己的字符；拼接式前缀会让"哪个软 token 对应哪个字"变成
   需要模型自己学的隐式对齐。
3. **投影层末端零初始化。** 初始时刻 `h_i = Embed(c_i)`，模型与纯文本模型
   **逐位相同**。这既是可控对照的前提（唯一变量是声学通道），也使通道
   必须"自己挣得"影响力；同时消除了 LLaVA 式两段训练中"随机投影注入噪声"
   这一动机。
4. **逐字符决策而非整句重写。** 2956 个字符错误中只有 2625 个可由逐字决策
   修复，其余 331 个是增删。整句重写会把增删一并卷入，代价见 §11 的
   destroyed 17。

**对齐的实现细节（关键且易错）**：编码器接受 4 个查询 token
（textnorm、language、event、emotion），因此 **CTC 帧 f 对应编码器帧 f+4**，
剥离后逐帧一一对应、**无需任何重采样**（在全部 17,301 条训练句上验证，
`enc_ctc_frame_mismatch: 0`）。强制对齐在**归一化**文本上进行（标点在
SenseVoice CTC 中不可发射），因此需要显式的 raw→normalized 索引映射把
声学向量挂回提示中渲染的**原始**假设字符上（22.9% 的训练行两者不同）。

## AC.3 受限解码

模型回复 `{"text":"<修正句>"}`。一旦生成进入 text 值内部，输出位置 p 只允许
发出

    { 假设[p] } ∪ { 该帧 CTC top-k 备选 }

且 p 随发出字符前进。替换在声学可信集内自由、在集外**不可能**。
这与 SEAL（arXiv 2501.08421）的受限解码目的一致：把幻觉从"靠提示词劝阻"
变成"结构上无法发生"。此前纯文本 SFT 臂的 off-pool 输出率是 **15.3%**，
是其失败的直接死因之一。

**边界处理**：文本值之外、值闭合之后、句子超出假设长度时，约束自动释放——
约束绝不能把模型困在无法结束的序列里。此外，掩码只能放行一个字符的**首 token**，
若某位置的允许集包含需要多 token 的字符，发出的 token 会解码成不完整字符、
位置不前进、模型被迫反复发出无法完成的 token。实测 4,943 个不同字符中
**530 个（10.7%）** 属此类，因此处理器在这些位置**释放**约束：
在真实 ST-CMDS 集合上释放 **4.39%** 的位置，保留 **95.61%（53,508/55,965）** 受约束。

## AC.4 两阶段训练

**阶段 1（对齐）**：冻结语言模型，只训投影层，任务为"看着声学软 token 复述"，
使投影层学会把声学表示翻译进 LLM 的输入空间。

**阶段 2（指令微调）**：投影层 + LoRA 联合训练，任务与纯文本基线**逐字节一致**
（同一提示模板、同一目标、同一全序列损失），唯一差别是声学通道。

**这是可控对照的关键**：在 300 行上逐 token 比对，本方法的 tokenization 与
基线训练器**300/300 完全一致**。因此任何行为差异都可归因于声学通道本身。

## AC.5 预注册判据

训练数据仅 AISHELL-train 17,301 行，与 ST-CMDS / THCHS-30 / AISHELL-dev 的
uttid 交集为 **0/0/0**。检查点在 AISHELL-dev 上选，ST-CMDS 与 THCHS-30 各做
**一次**迁移。

| 判据 | 门槛 |
|---|---|
| 门控精确率 | ≥ 70% |
| 净编辑字符 | > 0 |
| beyond-N-best imp | 不降 |
| 指定热词召回 | ≥ 95.98% |
| 保护跨度破坏数 | ≤ 0 |
| ST-CMDS CER | < 4.9356% |

**证伪条款（预注册）**：若联合门控的精确率**仍落在 54% 盈亏平衡附近**
（45–58% 带内），即判定"联合门控"假设为假，按负结果记录并**停止**，不再叠加补丁。
**特异性条款**：若改善只出现在 ST-CMDS 而在 AISHELL-dev / THCHS-30 上不出现，
则属于针对目标语料的适配、违反项目约束，**即使 headline 数字改善也废弃**。

盈亏平衡点的定义：一次正确编辑平均挽回 1.133 字，一次错误编辑损失 0.965 字，
故 `P* = 0.965 / (1.133 + 0.965) ≈ 0.662`；跨语料稳定在 0.613–0.672，
而编辑率先验在 AISHELL-train（61.4%）与 ST-CMDS（28.5%）之间相差 3 倍——
**判据可迁移，先验不可迁移**，这正是所有阈值只在训练域校准的依据。

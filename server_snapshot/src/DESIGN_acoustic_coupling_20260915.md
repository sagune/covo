# 耦合件设计：Acoustic-Conditioned COVO（AC-COVO）

**日期**：2026-09-15 · **依据**：`RESULTS_RERANK_20260914.md` §17（本次新增的测量）
**约束**：§15（不做数据集成/工程性补丁，所有改动必须论文可解释）

---

## 1. 为什么现在可以谈耦合：测量已经把缺口钉死了

§17 用**已有**的强制对齐测出三件事，它们共同指向唯一的架构结论：

| 事实 | 数值 | 含义 |
|---|---:|---|
| 参考字在声学自分布 top-5 内（排除 argmax） | **87.50%** | **内容在** |
| 参考字就是第一备选 | **58.82%** | **判据在**（> 54% 盈亏平衡） |
| 纯声学门控最优净收益 | **+48 字**（需 +434，相对前端 top-1 5.2722%→4.5%，56,163 参考字符） | **门控不在** |
| 逐帧声学 top-5 oracle CER | **1.1611%** | 可修空间 **4.09pp** |

所以：

> **CTC 头有声学、没有语境；LLM 有语境、没有声学。
> 缺的不是信息，是一个同时读到两者的联合函数。**

这就是"这两块模块之间应该放什么"的答案。用一句话说：
**把逐帧声学候选分布投影成 LLM 能读的软 token，让 LLM 用它来决定"哪个位置该动、以及动成哪个字"。**

注意 §17.2 已经排除了一个错误设计：**注入通道必须是"逐帧候选分布"，不是"N-best 列表"**——
逐帧 top-5 oracle（1.1611%）比整个 24 候选句级池 oracle（2.3254%）好一倍，
因为 N-best 只含前端愿意成句输出的替代。

## 2. 架构（对应论文范式）

与 **LLaVA / SALMONN / Ola** 的"冻结模态编码器 → 可训练投影 → LLM(LoRA)"两段式完全同构，
并采用 **SEAL（arXiv 2501.08421）** 的两个额外要点：**细粒度声学注入** + **受限解码抑制幻觉**。

```
音频 ──► CB-SenseVoice 编码器（冻结）──► 逐帧隐状态 H ∈ R^{T×D}
                                          │
                                          │  ← 同时取该帧 CTC 分布的 top-5 字与对数概率
                                          ▼
                            投影层 / 重采样器（可训练；MLP 或 Q-Former）
                                          │
                                          ▼
                               K 个声学软 token（K≈16–32）
                                          │
   文本提示（system + 逐帧候选表 + N-best）─┤
                                          ▼
                       Qwen3.5-9B（LoRA 可训练）
                                          │
                                          ▼
                     受限解码：只在"声学可信字符集"内产生替换
```

**四个设计决定及其依据**（全部来自测量，不是审美）：

1. **投影层的输入是逐帧隐状态 + 该帧 top-5 候选**，不是整段音频的摘要。
   依据：§17.1 的 87.5% 是**逐帧**统计；句级摘要会把位置信息抹掉。
2. **下采样到 K≈16–32 个软 token**。依据：SALMONN 的 Q-Former 窗口化；T≈60–100 帧直接拼接会挤占文本预算。
3. **受限解码（SEAL 式）**：输出被约束在"该位置声学 top-5 内的字"。
   依据：SFT 臂的 off-pool 输出率 **15.3%**，而 evidence 臂只有 1.6%——
   幻觉正是上一次失败的直接死因之一，必须结构性排除，而不是靠提示词恳求。
4. **逐字决策输出**，不是整句重写。依据：可修的 2625 个错字中 331 个是增删、
   逐字机制无法修复，整句重写会把它们卷进来（§11 的 destroyed 17→ 是这条路的代价）。

## 4. 训练：两段式（与 LLaVA/SALMONN 一致）

**Stage 1 — 对齐（冻结 LLM，只训投影层）**
任务不是纠错，而是"**看着声学软 token 复述这段话**"（caption 式），
让投影层学会把声学表示翻译成 LLM 的输入语言。若跳过这一步，
随机初始化的软 token 会在 Stage 2 早期被当成噪声，LoRA 会学会忽略它。

**Stage 2 — 指令微调（投影层 + LoRA）**
任务：给定音频软 token + 逐帧候选 + N-best，输出**逐字决策**（保留 / 替换为某候选）。
训练域**只有 AISHELL train 17,301 行**（§15 红线：不含任何 ST-CMDS/THCHS uttid）。

**为什么这次可能越过 54% 的门槛**：前几次失败的共同形态是"精确率落在盈亏平衡点上"
（45–54% vs 需要 54%）——信息量恰好等于代价。而 §17 表明，
**判别所需的信息（87.5% 内容 + 58.8% 条件赔率）此前从未被送进任何模型**：
文本臂只看到置信度数字，声学臂只有单字阈值。**联合函数的输入空间是全新的。**

## 5. 评估：预注册判据（跑之前定死）

同一协议：checkpoint 在 **AISHELL dev** 上选，**一次性**迁移 ST-CMDS + THCHS-30，
`restore[deployable]`，配对 bootstrap。

| 判据 | 门槛 | 不过则 |
|---|---|---|
| 门控精确率 | **≥ 70%** | 回退（§10.12 预注册值） |
| 净编辑字符 | **> 0** | 回退 |
| beyond-N-best imp | 不低于 baseline | 回退 |
| 指定热词召回 | 不低于 95.98% | 回退 |
| 保护片段破坏数 | 不高于 0 | 回退 |
| **ST-CMDS CER** | **< 4.9356%** | 未达标 |

**证伪条件（必须诚实执行）**：
- 若联合门控的精确率**又一次落在 54% 附近** ⇒ "联合函数"假设为假，
  在当前基座规模下此路不通，按负结果记录并停止，不再加补丁。
- 若只在 ST-CMDS 上改善、AISHELL dev / THCHS 不改善 ⇒ **数据集适配，违反 §15，废弃**。

## 7. 与"允许的改动"的合规性（§15）

| 可能被质疑为"工程补丁"的点 | 辩护 |
|---|---|
| 逐帧 top-5 候选注入 | SEAL/LLaVA 的标准做法；候选来自模型自身分布，非数据集构造 |
| 受限解码 | SEAL 的核心贡献；减少幻觉是通用机制 |
| 软 token 投影 | 多模态 LLM 的标准范式（Q-Former/MLP projector） |
| 阈值校准在 AISHELL | §15.2 已证赔率域跨域不变（P\* 0.613–0.672 稳定） |

**不含**：任何 ST-CMDS/THCHS 特化规则、任何手工字符表、任何针对特定样本的补丁。
